# 这是什么文件？（给不熟悉技术的读者）

**一句话**：这是一份**“我先把规矩定死”的公开凭证**。

它记录的是：在某个时刻（见文件里的 `frozen_at_utc`），我们**先把研究规矩冻结好**，
然后把「这份规矩的指纹」公开存在项目之外。因为这个文件一旦被公开保存，
**保存时间就不是我们自己说了算的了** —— 这就是所谓“**外部时间锚**”。

---

## 1. 这份文件是干什么的

- 它是 SEED_A 研究的**预注册 v3 的冻结锚**：把“先定规矩、再看结果”这件事
  **放到项目外面留个见证**。
- 它**只记录指纹**（几串校验码）和版本信息，**不记录任何研究内容**。

## 2. 它一定不包含什么（逐字段确认）

| 文件里的字段 | 是什么 | 是否含行情/业绩数据 |
|---|---|---|
| `anchor_kind` / `anchor_schema_version` / `project` | 标识这是什么、第几版 | 不含 |
| `record_id` / `record_version` | 预注册记录的编号与版本 | 不含 |
| `frozen_at_utc` | 冻结时刻（时间戳） | 不含 |
| `contract_digest_algorithm` | 用哪种算法算指纹 | 不含 |
| `contract_digests` | 四份契约的**指纹**（sha256 值） | 不含（只是校验码） |
| `hard_cap_outcome_trials` | 最多试几次的上限（数字 12） | 不含 |
| `statement` | 一句声明：本版本是唯一放行依据、旧版本不追认 | 不含 |
| `contains_market_data` / `contains_outcome_numbers` | 两个**自证**标志，都是 `false` | 本身就是“没有”的声明 |

**结论：这份文件里没有任何真实行情数据、没有策略参数表、没有胜率/收益/盈亏等业绩数字。**
它可以公开。

## 3. 怎么验证没有被改过（Windows）

1. 打开“命令提示符”或“PowerShell”，切到本文件所在目录；
2. 运行：

```
certutil -hashfile FX_SEED_A_PREREGISTRATION_RECORD_V3_20260919_01.anchor.json SHA256
```

3. 把输出的那串字符与本包里的记录值对比，应当等于：

```
50127084aa7790cfc8963d539ec7c2ac177a2755e98b37ba76c4c79266dcf84b
```

**重要提醒（很容易踩的坑）**：
- 这个文件**原本就没有尾随换行**，也**不要**用记事本/编辑器打开后“顺手保存”——
  多数编辑器会补一个换行，导致**哈希变化**，看起来就像“文件被改过”。
- 要验证，请**直接对下载/上传时的原始文件**算哈希，不要先编辑、不要先另存。

## 4. 它的效力范围（很重要）

- 这个锚**只对将来有效**：它证明的是“从这个时间点起，规矩已经先定好了”。
- 它**不能给过去背书**：过去那段历史（旧版本 v1–v2.3）仍然记为**不可核实、不追认**，
  这份锚**不能“洗白”过去**。
- 它**不等于研究放行、不等于允许动用真钱**。

## 5. “外部时间锚”到底指什么

**这份文件被公开保存的那一刻，就是外部时间锚。**
保存它的平台会留下一个第三方能看到的时间记录（提交时间 / 创建时间），
别人以后随时可以去那个平台核对“这个文件确实在那个时候就存在了”。
